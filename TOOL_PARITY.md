## Export workflows

**Export Layers to Files** renders each exportable raster, Smart Object, text, or shape layer through the normal compositor, preserving masks, vector masks, opacity, Blend-If and Layer Styles. It can export visible layers only, trim transparent bounds, include or strip File Info metadata, choose PNG/JPEG/WebP quality, and use a folder picker where supported with multi-download fallback elsewhere. Adjustment layers are skipped because they have no standalone pixels; isolated clipped layers are exported as independent artwork rather than disappearing without their clipping base.

## Apply Image

**Image → Apply Image…** can blend the merged result or an individual pixel-capable layer from any open document into the active layer. It supports RGB, Red, Green, Blue and Alpha source channels, invert, the editor's full blend-mode set, opacity, exact target-transparency preservation, different-size source clipping, and automatic active-selection masking. Raster offsets are respected and non-raster targets are rasterized through the normal mutation path. 32-bit HDR documents are intentionally blocked until Apply Image has scene-linear Float32 blend math instead of degrading HDR through Canvas compositing.

## Document resolution / print metadata

Documents now carry explicit **PPI resolution metadata** independently from pixel dimensions. New Document and Image Size expose Resolution; Image Size can change PPI without resampling pixels, matching the distinction between physical print size and raster dimensions. Crop and Perspective Crop may update PPI, project save/recovery preserves it, the Measure tool can calibrate physical units from it, the status bar reports it, and PSD import/export reads/writes Photoshop ResolutionInfo instead of hard-coding 72 DPI.

## Shared behavior standards

All pixel-editing tools should remain selection-aware and undoable. Raster content outside the document frame must remain preserved unless the user explicitly chooses destructive cropping. Tools that can reasonably sample a flattened view should distinguish **sampling source** from **output destination** so "Sample All Layers" never accidentally flattens visible layers into the target.

New tool work should prefer shared engines rather than duplicate implementations: selection tools should use the grayscale mask pipeline; brush-like tools should use common stroke/dynamics infrastructure; perceptual color-region tools should reuse the Wand matcher; and destructive operations should offer a new-layer or smart/non-destructive route where practical.

## Working precision

The editor now has three working-raster modes. **8-bit/channel** remains the universal compatibility path; capable browsers can retain a **16-bit floating-point working raster**; and **32-bit HDR documents** use authoritative scene-linear `Float32Array` RGBA backing stores with float16 canvas mirrors for display and interactive canvas edits. New Document exposes 8/16/32-bit depth, with sRGB/Display-P3 available where appropriate.

High-depth CPU filters and the pixel-worker path now operate on normalized floating pixel buffers instead of forcing every operation through legacy 8-bit `ImageData`. Project format version 5 preserves 16-bit canvas payloads, full Float32 HDR layer data, and captured source-file metadata alongside compatibility previews; older v1-v4 projects remain loadable. PSD/PSB decoding retains 16-bit samples, layered PSD export can write 16-bit channels, unknown Photoshop image resources/additional-layer-info blocks round-trip losslessly, and TIFF can export at 16-bit/channel.

The WebGL2 compositor can independently use **RGBA16F intermediate framebuffers** for supported layer blending and adjustment passes; the status bar reports that capability separately from document depth. Remaining precision work is concentrated in operations that inherently pass through Canvas2D/display mirrors, color-management/proofing behavior, and broader high-depth interchange rather than the core CPU pixel pipeline.
